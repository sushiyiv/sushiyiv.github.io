    虚拟机移动位置后网络问题解决方案

    概述 将 VMware 虚拟机文件夹移动到新的位置后，虚拟机网络异常。可能是选择了 “I moved it”，VMware 保留了原来的 UUID 和 MAC 地址，虽然网卡配置仍然存在，但仅重新添加 Network Adapter 并不能恢复网络。必须为虚拟网卡重新生成一个新的 MAC 地址后，Linux 才能够正确识别并建立网络链路。 在重新生成 MAC 地址后，手动执行： sudo ip link set ens33 up sudo dhclient ens33 即可正常获取 DHCP 地址并联网。 但重启系统后，网络再次失效。进一步排查发现，问题已经从网卡识别转变为 NetworkManager 未管理 ens33（unmanaged），导致系统开机不会自动启用网卡和自动获取 DHCP 地址。通过修改 NetworkManager 配置，使 ens33 恢复为 managed 状态后，最终实现了开机自动联网。 正文 这次问题其实是一个比较完整的 VMware + Ubuntu + NetworkManager 故障排查案例。我按照实际排查过程整理了一份完整流程，以后遇到类似问题可以直接按这个思路排查。 VMware Ubuntu 网卡无法联网故障排查记录 一、故障现象 虚拟机正常启动，但无法联网。 VMware 网络模式：NAT Connected 为灰色无法勾选 Connected at power on 已勾选 Ubuntu ip addr 结果： ...
